The swap test — what changes if you swap?

Swap = implementation

React → Vue. Same UI surface.
FastAPI → Flask. Same routes.
PostgreSQL → MySQL. Same shape.
Compose → K8s. Same stand-up.

Swap = contribution

Schema → 26 ungrounded labels. Loses grounding claim.
Loss → plain CE. Loses imbalance result.
KB → ungrounded LLM. Loses validation.
UI → notebook. Loses UAT evidence.

Engineering reasons — one phrase per layer

React + TSEcosystem + TypeScript support. Lowest-risk for inheritors. No research claim.
FastAPIAsync-native + first-class PyTorch + auto OpenAPI. Right shape for a single in-memory model worker.
In-processNo network hop ⇒ KB lookup stays at ~15 % of 150 ms budget. Remote KB ⇒ ~50 ms by itself.
PostgreSQLFTS + JSONB in one engine. Analytics needs both — country counts and nested 5W1H queries.
ComposeOne command. At 30 k articles/year, service mesh = overengineering.

VioNER

Pre-loaded interrupts

Q · "Isn't this just web engineering?"
Defend the stack as engineering, not research claims — right reading of the parts. The research is the INTEGRATION evaluated end-to-end. Slide 6 empty cell · §7.3 #5 · §6.10 UAT (n=5, 6/6 tasks).
Q · "Why monolith?"
At 30 k articles/year, single FastAPI worker holding 110 M-param BERT in memory = faster + simpler than mesh. KB in-memory ⇒ 15 % of 150 ms. Remote KB ⇒ ~50 ms by itself. Microservices fit much higher load.
Q · "Why React (not Vue)?"
Ecosystem + TypeScript support — lowest-risk for inheritors. Swap test: React→Vue changes implementation, not contribution. UI being React vs Vue doesn't change the integration claim or whether UAT validates it.
Q · "How do you know analysts can use it?"
F1 doesn't — UAT does. §6.10: n=5 (2 EW analysts + 1 academic + 2 NLP devs) · 6/6 tasks all completed. Likert 4.6/5 on 5W1H clarity; 4.0/5 on training screen (drove future work). Slide 19 deepens.
