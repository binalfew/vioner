The F1 chain — whiteboard-ready

Pre-loaded interrupts

Q · "Why F1, not accuracy?"
78 % of tokens are O ⇒ predict-O-everywhere scores 78 % accuracy, 0.0 F1. F1 ignores correct O entirely — measures only entity recovery. The two metrics maximally disagree about a know-nothing model; F1 tells the truth.
Q · "Why is micro higher than macro?"
Micro pools counts ⇒ high-support dominates (ACTOR 47.6 k vs VICTIM 5.5 k). Macro weights equally. Gap positive because high-support entities have highest F1 — the reassuring direction.
Q · "Leakage between train and validation?"
Three defences in order: article-level split · hash dedup before split · augmentation template pools partitioned. Then volunteer §6.13: residual wire-copy risk listed honestly.
Q · "Lucky seed?"
3 seeds (42, 17, 91) · variance ±0.4 pp macro F1. Ablation gains exceed noise by an order of magnitude — VICTIM gain ≈ 25× seed noise. Paired bootstrap p < 0.01. §6.4 / §6.6.

Delivery traps to avoid

  • Hedged numbers ("about point nine") ⇒ reads as not knowing your own results. Full precision, always.
  • Letting the panel discover the accuracy inflation first ⇒ 96.7 % then reads as attempted inflation. Demote it yourself.
  • CoNLL comparison in the default run ⇒ overruns the window. It answers "is 0.909 good?" only.
  • Claiming "better than CoNLL" ⇒ false (0.909 < 0.92). The claim is "competitive on a harder distribution".
  • Delivering the per-entity ranking here ⇒ steals slide 17. Name VICTIM as weakest if forced; defer the map.
  • Expanding micro/macro into full arithmetic on stage ⇒ one sentence suffices; the table is on screen.
